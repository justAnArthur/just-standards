# M7: runs that see their own CI and preview

The first real batch (three acadsys PRs, 30–50 s and $0.25 each) showed where a run stopped short:

- The worktree had no `node_modules`, so no worker ran typecheck or tests. One PR broke the build, and only CI caught it.
- A worker that needed a video from a person still opened a ready PR.
- The PR previews sit behind Vercel's sign-in, so nothing checked them before a merge.
- The AI hero check read the page through WebFetch, which hands the model a summary. Its quotes were not the page's text.

## Dependencies in the worktree
- **`fix` installs dependencies** in the new worktree before the worker starts.
  - The lockfile names the package manager: `bun install --frozen-lockfile`, `pnpm install --frozen-lockfile`, `yarn install --frozen-lockfile` or `npm ci`. It runs with `CI=1`, for up to 10 minutes.
  - The run record gets `setup: { command, ok, error? }`, and the prompt says how it went. When the install failed, the prompt carries the end of its output, and the worker installs dependencies itself.
- **That package manager joins the worker's allowed tools** (`Bash(pnpm *)`, for example), so the worker can run the repo's scripts.

## Waiting for CI
- **After opening the PR, the worker waits for its checks** with `gh pr checks <n> --watch`.
  - When a check fails, it reads the log (`gh run view <id> --log-failed`), fixes the cause, pushes and waits again.
  - After two rounds of fixes, or when a failing check has no log it can read, it stops and reports what still fails as missing.
- **Every run may run `gh pr checks` and `gh run view`.** These are added to the worker's allowed tools.

## Drafts
- **`missing` means what a person must provide or fix before the PR can merge.** Checks to run after merging go in the PR body. The `finish` tool's description and the prompt both say so.
- **A run that ends with `missing` makes its PR a draft** (`gh pr ready --undo`), whatever the worker opened. The record has `pr.draft`, and `runs sync` keeps it current.

## Checking the preview
- **When a run ends with a PR, its items are checked on the PR's preview.**
  - The preview is the newest successful GitHub deployment of the head commit, which Vercel, Netlify and Cloudflare all report.
  - `runs sync` checks again for a new head commit, and until a preview answers.
  - The results go to the record's `preview: { sha, checked_at, url?, results, note? }`. Nothing is written to the grid's results, which stay about the live site.
- **The app shows them as "On the preview"** in the run pane, and reading a PR first runs `runs sync <run>`.
- **A protected Vercel preview** answers 401, or redirects to vercel.com's sign-in. The check then stops with a note saying what to set.
  - Set `vercel_bypass` on the asset to the name of a secret.
  - Put the secret in the workspace's `secrets.yml` (git-ignored; `workspace init` ignores it): the project's *Protection Bypass for Automation*, from Vercel › Project › Settings › Deployment Protection.
  - Every request to the preview's origin then carries `x-vercel-protection-bypass`, including the requests a script check or an `og:video` follow makes.

```yaml
# businesses/acadsys.yml
assets:
  - { id: site, kind: website, url: https://acadsys.com, repo: utegsk/acadsys-www, vercel_bypass: acadsys-vercel }
```

```yaml
# secrets.yml
acadsys-vercel: <the bypass secret>
```

## AI checks read the HTML
- **The engine fetches the pages an AI check names**: `pages`, default `['/']`, relative to the asset's URL, or to the preview's.
- **It strips what a reader doesn't see** (scripts, styles, SVG, comments, class names) and caps each page at 60,000 characters. The result goes into the prompt, on stdin.
- **The model has no WebFetch.** Its evidence quotes the HTML exactly. On acadsys the hero check went from 28 s to 9 s, and its quote came out right.

## CLI
- `runs sync [run…]`: syncs only those runs. The app calls it with one run when it reads that run's PR.
