# M6: onboarding, worker permissions, finishing a run, GitHub

M5 made fix runs work. M6 makes the app usable without editing YAML or clicking Allow on every command, and closes the loop from a run to a merged PR.

## Engine (`standards` CLI)

### Workers
- **`permission_mode`** takes Claude Code's modes: `manual` (asks for everything), `acceptEdits` (the default), `auto` (Claude Code decides what is safe to run), `dontAsk`, `plan` and `bypassPermissions` (runs anything inside the worktree). The old `default` value still reads, as `manual`.
- **`standards worker set --json '<Worker>'`** adds or replaces a worker in `workers.yml`.
- **`standards worker remove <id>`** deletes one.
- **`standards worker allow <id> <rule>`** appends a rule such as `Bash(python3 -)` to the worker's `allow` list, without duplicates. The app calls it when a permission question is answered with "Always allow".

### Businesses and workspace
- **`standards business set --json '<Business>'`** writes `businesses/<id>.yml`.
- **`standards business remove <id>`** deletes it.
- **`standards workspace init <dir>`** creates `businesses/`, a `workers.yml` with the default presets (`sonnet-fixer`, `opus-fixer`, `opus-reviewer`) and a `.gitignore` for `.state/`.
- **How writes happen:** every write is validated with the zod schema first, and written with `Bun.YAML.stringify`.

### Clone
**`standards clone <business> <asset> [--into <dir>]`**
- For an asset with a `repo` and no `path`.
- Runs `gh repo clone` into `~/Projects/<owner>/<name>`, or `--into`.
- If that folder is already a checkout of the repo, it is reused.
- Sets `path` on the asset and prints `{"path": …}`.

### Finishing a run
- **`standards mcp --run <id>`** is a small MCP server on stdio. It has one tool, `finish`:
  - input `{ pr_url?: string, summary: string, missing?: string[] }`;
  - it writes `.state/runs/<id>/finish.json`.
- **How `fix` uses it:**
  - it passes the server with `--mcp-config` and allows `mcp__standards__finish`;
  - the prompt ends with: when you are done, call `finish` with the PR URL, a short summary and anything a person must still do, then stop.
- **The run record** gains `summary?: string` and `missing?: string[]`.
- **Which PR counts:** a PR given to `finish` wins over the one parsed from the text or found with `gh pr list`.

### Pull requests
- **`standards pr view <run-id>`** prints:

  ```json
  { "number": 1, "url": "…", "title": "…", "state": "OPEN|MERGED|CLOSED", "isDraft": false,
    "mergeable": "MERGEABLE|CONFLICTING|UNKNOWN", "mergeStateStatus": "…", "reviewDecision": "…",
    "checks": [{ "name": "…", "state": "…", "conclusion": "…" }],
    "additions": 0, "deletions": 0, "changedFiles": 0,
    "files": [{ "path": "…", "additions": 0, "deletions": 0 }], "body": "…" }
  ```

  All of it comes from `gh pr view --json`.
- **`standards pr merge <run-id> [--method merge|squash|rebase]`** merges with `gh pr merge`, then does what `runs sync` does for that run: updates the record, removes the worktree and deletes the merged branch. It prints the updated record.

### GitHub
- **`standards github status`** prints `{"loggedIn": bool, "user"?: string, "protocol"?: string}`, read from `gh auth status`.
- **`standards github login`** runs `gh auth login --hostname github.com --git-protocol https --web` and passes its output and stdin through. The app shows the one-time code and sends Enter.

## Kit (`@justanarthur/modo-ui-standards`)
- **Transcript:** `@justanarthur/modo-ui-ai` goes to `^0.6.2` and `RunTranscript` uses its current `Transcript`. A fix run's long prompt shows as a collapsed task card, not a full chat bubble.
- **`PrDetail`:**
  - title, state, draft, review decision;
  - the checks with their states;
  - additions and deletions, the files, and the body as Markdown;
  - actions: Merge ▾ (merge, squash, rebase), Open on GitHub, Re-check.
- **`WorkerForm`:**
  - id, model, effort and profile;
  - the permission level as a segmented choice with one line each: Ask for everything, Allow edits, Auto, Trusted (bypass);
  - the allowed tools as editable chips.
- **`BusinessForm`:**
  - name and id;
  - the assets: kind, URL, repo, path (with a Clone action when there is a repo and no path), stack;
  - the packs, with the version each one follows.
- **`Onboarding`:** the steps workspace folder → Claude Code profile → GitHub → first business, each with its status and action.
- **`GithubStatus`:** signed in as whom, or a Sign in button showing the device code.

## App
- **First launch:** a missing or empty workspace opens Onboarding.
- **Editing config:** Add business on the Businesses screen, Edit on a business, Add and Edit on the Workers screen. All of these go through the `business` and `worker` commands.
- **Always allow** in a permission question also runs `standards worker allow`.
- **Clone** from an asset row or the business form, for assets without `path`.
- **When a run ends with a PR**, the pane switches to `PrDetail`, loaded with `standards pr view`. Merge runs `pr merge`, then re-checks the run's cells.
- **Settings and onboarding** show `GithubStatus`.
